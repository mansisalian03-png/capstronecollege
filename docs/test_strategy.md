# Test Strategy

## 1. Automated Testing (pytest)
- **Unit Tests**:
  - Pydantic models for validation and schema enforcement.
  - NLP extractor functions (given a specific string, does it extract the exact known tuple of entities?).
  - Graph functions (does a mocked graph traversal correctly identify the 2 downstream products for a given supplier?).
- **Integration Tests**:
  - FastAPI endpoints (using `TestClient` to mock requests).
  - Database interactions (using a test SQLite/Postgres container).
- **Robustness Tests**:
  - Submit empty payloads, malformed JSON, and non-English text to the API.
  - Flood the deduplication module with identical strings to ensure it returns exactly 1 event.

## 2. Evaluation Metrics (Implemented in Code)
Because this is an ML-driven pipeline, standard software tests are insufficient. The pipeline will output the following metrics automatically to MLflow:

1. **Extraction F1 Score**: Compare the spaCy/HF pipeline's extracted entities against a manually labeled baseline of 20 articles.
2. **Alert Precision**: Out of all alerts generated by the system, what percentage were `accepted` by the simulated analyst feedback?
3. **Duplicate Reduction Rate**: `1 - (Post_Dedup_Events / Pre_Dedup_Events)`.
4. **Lead Time**: Simulated `Event_Timestamp` minus `Alert_Generation_Timestamp`.

## 3. Baseline Comparison
The system will be tested against a naive baseline to prove the value of the NLP graph pipeline:
- **Baseline Model**: Keyword matching (e.g., `if "fire" in text and "Supplier A" in text: alert()`).
- **Target Comparison**: The NLP model must outperform the baseline in Alert Precision (fewer false positives) and Recall.
